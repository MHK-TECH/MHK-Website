About me

I'm M-Huzaifa Khilji. I live in Lahore, Pakistan. I build data systems, train models, and spend my free time on math problems nobody has solved.

What I do

I work at the intersection of data science, AI, and engineering. Not just building models — building the entire system around them. The data pipelines that feed them, the dashboards that visualize them, the APIs that serve them, and the infrastructure that keeps it all running.

Some of what I build:

  • AI chatbots and document QA systems using RAG pipelines
  • Real-time dashboards for business intelligence
  • Data pipelines that process millions of records daily
  • Fine-tuned LLMs for domain-specific tasks
  • Automated workflows using n8n and custom code
  • Full-stack web and mobile applications
  • Oracle ERP/CRM customization and migration

How I work

I believe in building things that last. Not demos. Not prototypes that break the moment someone touches them. Production systems that run while I sleep and don't need babysitting.

That means:

  • Simple first. If a spreadsheet solves the problem, I'll suggest a spreadsheet. Not everything needs a neural network.
  • Measure everything. I don't guess about performance, accuracy, or speed. I measure. Then I optimize what matters.
  • Fail loudly. I build monitoring and alerting into everything. If something breaks at 3am, I know about it before the client does.
  • Ship, then iterate. Perfect is the enemy of deployed. Get it working, then get it better.

What I care about

  • Things that work. Not demos. Not prototypes. Production systems that run while I sleep.
  • Things that matter. Dashboards that get used. Models that save money. Pipelines that don't break at 3am.
  • Hard problems. I spend time on the Millennium Prize Problems because they make me think differently about everything else.
  • Clean code. Not pretty code. Code that the next person (including future me) can understand and modify.

What I don't do

  • I don't build things that don't solve a real problem.
  • I don't use AI to write my code. I use it to think faster.
  • I don't believe in "move fast and break things" when the thing is a database.
  • I don't chase trends. If a new framework doesn't solve a problem I have, I ignore it.
  • I don't over-engineer. The simplest solution that works is the best solution.

The research thing

I spend time on the Millennium Prize Problems. Not because I'll solve them — I probably won't. But because the work teaches me things I can't learn anywhere else.

Working on the Riemann Hypothesis teaches you about pattern recognition. P vs NP teaches you about computational limits. Navier-Stokes teaches you about physics-informed modeling. These skills transfer directly to the AI and data science work I do professionally.

You can read more about my research on the research page.

Before data science

I studied computer science. I was always more interested in the hard problems than the popular ones. While everyone was building CRUD apps, I was reading about neural networks and number theory.

Data science felt like the right place — it combines math, code, and real-world impact. You can build a model that saves a company millions, automates a tedious task, or discovers something nobody knew before. That's interesting work.
